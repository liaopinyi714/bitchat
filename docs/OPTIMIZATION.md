# 0.2.4 整体优化说明

本轮覆盖 Android 在线传输、共享收包队列、私聊存储、图片处理、Cloudflare 中继和发行工具。目标是消除已确认的并发窗口、减少不必要的工作，并让发布检查能发现拿错产物。原版界面布局、操作入口、频道规则、Noise 和频道加密格式继续兼容。

## 在线与本地传输

多个频道同时连接时，接收回调会广播到其他连接。原实现的接收和发送共用同一监视锁，可能出现连接之间互相等待。发送队列改用独立锁，业务帧统一受 1 MiB 待发送上限保护。私聊重试的发送及失败通知移到锁外，单个对端异常不再终止其他消息的重试。

邮箱短时重连时，新发给已知在线联系人身份的文字仍能进入运行中的有界发件箱。房间成员与邮箱活动分开记录，离开最后一个共同频道不会立即删除仍有邮箱流量的私聊会话。缓存身份不等于在线；邮箱活动超过 3 分钟过期，断开本机邮箱连接立即失去在线状态。这是近期活动判断，不是永久的全站在线目录。私聊目标另保留在本进程的路由缓存中，过期或普通停止后仍能主动重新握手；panic 会清除该缓存。

停止服务时拒收并取消当前生命周期的收发任务，丢弃排队的旧包和实时语音。若已有同步加密或存储操作尚未返回，重启会在后台等待它退出，再清理状态、激活新一代工作并重新公告和同步。本传输的状态检查与同步入队共用生命周期锁，Cloudflare 每个文件分片另核对传输代次，防止重启后续发旧片；跨 Core 桥接调用保留在锁外，避免交叉持锁。已准备文件提交同样核对代次。进程退出后的发件箱和目标缓存恢复仍不在本次范围内。

共享 PacketProcessor 现在原子地创建每个发送者的顺序消费队列，使用非阻塞入队，避免每包新建协程、无限积压以及异常后绕过顺序处理。单个发送者最多排队 256 包，全局等待队列按包内容及固定开销估算约 16 MiB，最多同时保留 256 个忙碌消费者；已空闲消费者立即让位，闲置 60 秒自动回收。这些是瞬时资源保护，不是联系人、频道或软件总规模的上限，也不代表整个进程只使用 16 MiB 内存。

满载时立即拒绝入队，不阻塞蓝牙、Wi-Fi 或 WebSocket 回调。在线邮箱不确认临时拒绝的包，并退避重连，让服务器原有离线包保留待投；永久拒收的内容仍会消费，避免无限回放。本地无线入口没有同等持久重放保证，极端过载时会丢弃超量包，由已有协议重试或同步恢复；不能据此承诺大附件必达。

`received` 只代表客户端传输已接纳，不等于数据库保存或用户已读。私聊 `Delivered` 继续要求接收端成功保存，在线文字保留 0.2.3 的 100 条 / 5 分钟重试边界，尚未增加跨进程持久发件箱。

## 私聊存储

历史加载、入队写入、读状态、删除与撤销均核对同一生命周期，清空或 panic 后旧任务不能恢复旧内容。取消持久写入会释放消息 ID 的预留，后续合法重试可继续。

重复 ID 不再自动把不相关的会话合并。数据库先检查已存消息的发送身份、正文、类型及会话关联；已确认的合法重复不再重新加密和插入。打开一个会话只统计该会话的未读，而非查询全部消息，并能用零未读快照清除旧角标。没有数据库 schema 迁移，已保存的发送时昵称保持原有语义。

## 图片与文件生命周期

相册和相机图片先读取尺寸，再采样解码；旋转和镜像遵循 EXIF。发送仍按原来的最长边 512 像素、JPEG 质量 85 处理。图片预览移到最多两个并行的后台解码任务，按显示尺寸加载，单次解码额外设约 4 百万像素预算；保存图片仍复制原文件。

以合成 8000×6000 图片为例，准备 512 像素发送图时先采样为 1000×750：按 ARGB_8888 的像素缓冲计算，从约 183 MiB 降为约 2.9 MiB，再缩至发送尺寸。这是算法输入和像素量计算，不是整机峰值、耗电或帧率实测；旋转、编码及同时可见的图片仍有其他开销。

准备开始时冻结私聊或频道目标，切换聊天不会改变正在处理图片的收件人。取消时清理未交付输出和临时相机原图；从未交付界面的已解码位图也及时释放。导出到系统下载目录只有完整写入、关闭并发布成功才提示成功；失败则删除临时条目。

## Worker 与发行工具

Worker 在异步哈希后重新读取连接状态，防止旧快照覆盖限流计数或恢复失效连接。关闭、异常及改频道保护后立即隔离旧连接，避免假投递阻止离线入队。超大帧在编码前先检查字符串长度，减少拒绝前的额外分配。现有队列容量、TTL、保留范围和线协议均兼容，无需迁移数据库；服务器修复需要维护者重新部署 Worker。

Release APK 内加入不含本机路径的源码内容指纹。签名和打包工具重新计算并核对，防止同版本旧 APK 被写成新提交的 BUILDINFO。最终打包还要求编译输入实际包含在当前提交里，拒绝被 Git 忽略的额外源码。核对范围包括手机 main/release 源码、资源、原生库、Gradle 配置与依赖定义，具体规则随 BUILDINFO 发布；不覆盖文档、测试、机器配置或外部工具链覆盖项，也不构成独立可复现构建证明。

发行工具另检查旧包应用标识与 versionCode 递增、各架构公共资源及对应原生库一致性。签名和打包都先在临时目录验证，成功后原子改名为正式目录，失败不会留下看似完整的发行目录。临时内容仅在本地，不上传密钥、密码或日志。

## 验证与使用

具体测试数量、构建和产物检查见 [验证记录](TESTING.md)。新增测试使用合成身份、消息、图片及受控调度，覆盖乱序、取消、并发锁、队列饱和、缓存过期和失败输出清理。

尚需 [双机与长期使用验收](OPERATIONS.md)：覆盖移动数据私聊、多个频道同时重连、离开频道继续私聊、大图选择与取消、清空期间的异步工作、锁屏后台以及 BLE / Wi-Fi Aware 高负载。未把代码检查和自动回归写成实际运营商网络、硬件加密密钥库或整机性能验收。
