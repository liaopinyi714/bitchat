# bitchat 0.2.1 — 稳定性修复

基于官方 Android bitchat v2.0.1 的独立 GPL-3.0 分支。手机最低 Android 14（API 34），应用标识 `xyz.liaopinyi714.bitchat`，versionCode 9。继续使用 0.2.0 的长期发行证书和公开迁移链。

## 已修复

- 蓝牙连接现在等到通知订阅成功才报告可用，失败立即清理；连接建立超过 45 秒没有完成时释放资源，迟到回调不能恢复旧连接。
- GATT 服务端撤销权限后安全停止；回调与停止串行处理，旧连接的延迟任务不会通知新连接。重复订阅不累积设备，取消订阅会移除设备。
- 连接清理循环可反复启停，不积累协程；清理旧连接尝试时不删除同时建立的新尝试。
- 系统拒绝后台启动、启动期间撤销权限时避免异常退出；前台服务先完成系统要求的前台提升，再初始化传输。
- 文件解析先验证整个包、一次分配内容空间，避免很多小内容块导致反复复制和内存压力。传输格式和未知字段兼容规则不变。
- 修正数量资源及代码缩进问题，删除旧 Lint 基线，启用错误阻止构建。保留的社区语言包缺译按英文回退并保留警告；中文完整性和参数格式由强制测试覆盖。
- 移除未使用的媒体库读取权限；选择图片、文件仍使用 Android 系统选择器。保持没有定位权限、没有地图或地理频道入口。

没有重设计原版 UI，没有改变频道加密格式、Noise 算法或 Worker 存储结构。新消息使用新昵称，旧消息保留发送时昵称。

## 安装与升级

主流手机使用 `bitchat-android-arm64-v8a.apk`；不确定架构使用 `bitchat-android-universal.apk`。附件 `BUILDINFO.json` 给出文件大小、源码提交、工具链及公共证书指纹；`SHA256SUMS` 用于校验下载文件。

0.2.0 可用同一发行证书覆盖升级。匹配原开发证书的本分支旧安装可通过 v3 迁移链升级；原版官方应用或其他密钥签名的包不在承接范围。遇到签名冲突请保留原安装，卸载会删除身份和本地数据。

## 验证范围

自动检查覆盖手机 / Wear 构建、JVM / Robolectric 回归、协议契约、严格 Lint、Worker 类型与本地集成测试、部署预演，以及 APK 签名、迁移链、资源保留和 16 KB 对齐。完整数量与限制见 [测试记录](https://github.com/liaopinyi714/bitchat/blob/v0.2.1/docs/TESTING.md)。

手机 **665 项**、Wear **217 项**、Worker **22 项**测试全部通过，无跳过用例；手机与 Wear 的 Lint 错误均为零。406 项社区语言缺译被明确调整为警告，并没有宣称这些翻译已经补完。

真实 BLE / Wi-Fi Aware、覆盖升级的数据保留、厂商后台策略和持续使用尚需两台实体手机验收；自动测试不代表这些场景已经实测。按 [使用前验收](https://github.com/liaopinyi714/bitchat/blob/v0.2.1/docs/OPERATIONS.md) 完成后再将预发行转正，不用“零 Lint 错误”代替长期运行结论。
