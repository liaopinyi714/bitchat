# 代码检查与维护记录

这份记录针对本分支的 Android / Cloudflare 接入及相关消息状态。对照基线为官方 Android v2.0.1；它记录检查范围和可复现结果，不代表已经逐行审计所有上游代码或完成真机验收。

## 0.2.0 发行检查

复查客户端连接、消息身份、加密边界、持久化反射规则、权限与升级，以及 Worker 的认证、频道 / 邮箱路由、容量、休眠、队列过期和确认。沿用现有协议向量和回归，没有更换密码学算法或存储格式，也没有重新设计用户界面。

本次发现并修复的实际问题：

| 问题 | 触发方式 | 修复与回归 |
| --- | --- | --- |
| GATT 资源未关闭 | 停止后清空表，延迟任务读取空表或随协程取消 | 先取快照和清理状态，返回前逐一释放；撤销权限或重复停止也能完成其他连接清理 |
| 扫描器 / GATT 服务停止被跳过 | 停止函数排入任务后立即取消所属 scope | 同步停止；权限撤销也清除扫描状态，服务端关闭失败仍清除引用 |
| 尚在协商的连接泄漏或旧回调恢复连接 | MTU 前停止，随后迟到回调或迅速重启 | 跟踪待连接 GATT，按生命周期拒绝旧回调；服务端回调也绑定创建时生命周期 |
| 语言切换后部分文本仍用旧资源 | Compose 重组依赖普通 Context.getString | 使用 stringResource 获取进度和无障碍文案，保留布局与文本本身 |
| 发行身份依赖本机 debug 证书 | 换构建机器或丢失开发环境后发行 | 独立长期密钥、公共证书固定与签名迁移链；新增实际 APK 验证及附件打包工具 |

新增 12 项蓝牙回归使用合成地址、模拟 GATT 和虚拟调度器，覆盖同步释放、取消 scope、权限撤销、重复停止、待协商连接、迟到回调和重启。共享源码与测试同步进入 Wear。物理链路行为和升级数据保留仍需 [使用前验收](OPERATIONS.md)。

## 0.1.6 安装包精简

推荐 ARM64 精简预览代替通用 debug 日常安装，保留其他三种架构与通用包。手机最低 SDK 提高到 API 34，Wear 的最低 SDK 保持 API 33；旧定位权限从手机合并清单移除。R8 规则补齐反射读取的持久化模型，防止旧安装升级后 JSON 字段名称变化。

APK 检查直接读取产物中的 DEX，核对历史字段、JNI 与 WorkManager 入口，检查语言、字体、离线扫码和对齐，并对比各架构包的代码及资源。原包对比包括原生库和静态资产字节以及本地开发覆盖签名。没有改动用户界面、传输或加密算法。仍需在真机上用精简包验证冷启动、旧数据升级、权限、媒体及离线传输；不能把 debug 的单元测试成功当作 R8 后全功能已实测。

## 0.1.5 修复

| 问题 | 触发方式 | 最终行为 |
| --- | --- | --- |
| 失败连接在退避期间被旧回调恢复 | socket 失败后，旧连接迟到发送 challenge / ready | 失败时立即废弃连接 generation；旧回调不能认证或显示在线，只有新连接完成认证才能就绪 |
| 私聊对端收不到昵称更新 | 已知在线私聊对端没有共用频道，用户修改昵称 | 同一份签名公告通过该对端邮箱发送；不向无关频道广播，不从联系人历史枚举新目标 |
| 同名消息错误标为已读 | 对端使用与本机相同的昵称，在未打开的私聊中发送 | 未读及持久化优先按身份判断；自己的旧昵称消息仍属于自己，同名他人仍计为未读 |
| Android 模块说明与分支不符 | 直接阅读 android/README.md | 明确说明独立分支、实际功能、GPL-3.0 和正确构建 / 发行入口 |

上述连接与消息问题均保留最小合成回归。公告测试使用模拟 WebSocket、合成密钥和虚拟调度器，检查实际输出的数据包；未连接生产中继。身份判断由消息模型提供，UI、未读状态和会话显示名称共用同一规则；没有身份字段的历史消息才使用昵称回退。

## 核对范围

- 对照上游 UI 源码：聊天页、头部、输入框、私聊操作、消息分组、身份验证、关于页及频道入口。保留上游组件和布局；地理入口替换、分支说明及中文文案属于本分支修改。源码对照不能替代真机视觉和交互检查。
- 检查命名频道规范、入站频道校验、加入 / 退出、异步密码派生、服务器确认与 panic 失效处理。保持协议 v1 和现有黄金向量；本次没有修改频道加密格式或 Noise 算法。
- 检查 Worker 身份证明、频道 / 邮箱隔离、包大小、限流、创建者权限、休眠恢复、密文队列确认与过期；重新运行中继自动检查。
- 核对 README、使用、部署、构建、协议、安全和贡献说明。区分开发 APK、正式签名、自动测试和真实部署验收。

完整命令、结果和 Lint 的既有问题见 [测试记录](TESTING.md)。未完成事项见 [功能验收](FEATURES.md) 和 [Android 真机验收](ANDROID.md#必须完成的真机验收)。安全边界见 [安全说明](../SECURITY.md)。

## 后续维护顺序

1. 双机验证改名后的本机和对端显示、旧消息标签、同名未读、回执，以及长断网恢复。
2. 按 Android 验收文档检查真实 BLE / Wi-Fi Aware、频道媒体、PTT、后台和 panic。失败时先记录合成复现步骤，不用自动测试成功代替真机结论。
3. 按类别处理现有 Lint 问题；保留有效检查，不通过关闭检查制造零错误报告。
4. 备份长期发行密钥；完成真实设备验收后再将候选 Release 转正，后续补充独立双重构建证据。
