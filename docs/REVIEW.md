# 代码检查与维护记录

这份记录针对本分支的 Android / Cloudflare 接入及相关消息状态。对照基线为官方 Android v2.0.1；它记录检查范围和可复现结果，不代表已经逐行审计所有上游代码或完成真机验收。

## 0.2.4 整体优化检查

本轮并行检查传输、存储、中继及发行工具，并交叉复核异步图片处理。确认并修复多连接交叉持锁、无界收包队列、单一发送失败影响全部重试、清空后的旧持久化任务、重复 ID 错误合并会话、主线程完整解码大图，以及 Worker 异步状态覆盖。

新增图片后台处理时另通过交叉审查发现发送目标可能随切换会话漂移、取消时残留临时文件，已在发布前修复并补受控调度回归。发行工具则增加 APK 内源码指纹，拒绝同版本旧包冒充新提交、版本降级与各架构混包；失败输出在临时目录清理。

最后交叉检查补齐私聊活动过期后的主动握手，以及停止 / 重启时旧接收和发送任务的隔离；重启等待尚在执行的旧操作退出后再公告和同步，panic 不保留私聊目标。发行打包另核对所有来源输入均属于当前提交，避免忽略目录中的源码混入 APK。

具体取舍、资源上限、图片像素缓冲计算和部署要求见 [整体优化说明](OPTIMIZATION.md)。保留原版 UI、功能及签名和加密检查。整机耗电、帧率和长期无线可靠性尚待实体设备测量。

## 0.2.3 在线私聊检查

用户在关闭 Wi-Fi / 蓝牙、仅使用移动数据时，观察到私聊未显示而发送端标成已收到。代码检查确认两个缺陷：统一路由只检查旧对端记录与 Noise 会话，没有核对无线开关；消息处理接口丢弃了持久接收的布尔结果，接收失败后仍无条件发送送达回执。

路由现核对实际无线与权限，已关闭的本地通道不能截获在线私聊。私聊入库结果逐层返回，拒绝保存不发回执；数据库中的发送身份、正文、类型一致时允许重复确认，不重复发布 UI 事件。在线文字发件箱等待目标对端的加密确认，重连后重新加密尝试，最多 100 条 / 5 分钟，停止服务清除内存状态；没有宣称跨进程持久重试。

新增合成回归验证无本地传输时的服务器邮箱接收链路及先保存后确认。自动回归不证明具体手机和公网中的实际结果，仍需两台手机用 0.2.3 双向复测。Worker、Noise 算法与通信线格式未改动，不需更新 Cloudflare 部署。

## 0.2.2 权限页边距检查

用户反馈权限说明页底部有一条颜色不同的系统导航区域。代码确认：外层 Scaffold 在整页之前应用系统边距，导致底部 Surface 无法覆盖导航区域；主题还把系统导航栏强制设为页面背景色，与按钮栏的 surface 色不同。

权限页现在自行管理边距：背景绘制覆盖整个窗口，底部按钮内容单独避让系统区域，正文按按钮栏实测高度留出空间。主题保持透明导航栏，并同步深浅色导航图标。保留原文案、字号、字体、配色、按钮及权限行为。实现依据 [Compose 系统边距说明](https://developer.android.com/develop/ui/compose/system/insets-ui)；真机外观检查范围见 [测试记录](TESTING.md)。

## 0.2.1 收尾检查

针对上次留下的权限、Lint 和运行问题继续修复，具体变化为：

- GATT 以通知订阅的成功回调为连接可用条件；拒绝发现、订阅失败或 45 秒未完成建立都会释放连接，完成后取消超时任务。
- 服务端回调和停止共用同步锁，响应期间撤销权限会停止并清空连接；重复订阅去重，取消订阅移除设备，延迟公告验证具体 link ID。
- 周期清理任务可重复启动且只有一个实例，停止取消任务；并发更新后的连接尝试不会被旧快照删除。广告重试任务在停止时取消并检查生命周期。
- 系统拒绝前台服务启动和权限竞争不再导致未处理异常；开机接收器只处理合法 action，前台提升早于传输初始化。
- 文件解析保留混合宽度 TLV 协议和未知扩展兼容，完整检查长度后一次分配内容，避免多内容块反复拼接的平方级内存复制。
- 修正数量资源、移除未使用的媒体读取权限。应用继续通过系统选择器访问用户选择的文件，无需媒体库授权。
- 删除 Lint 基线并强制错误阻止构建。社区语言缺译被明确保留为警告；这属于检查策略调整，不能计为翻译已完成。中文完整性测试继续强制执行。

UI、密码派生、Noise、频道线格式和 Worker 存储没有改变。新增回归以及完整测试、Lint、产物检查结果见 [测试记录](TESTING.md)。仍未进行实体无线链路、设备升级和持续使用验收；没有编造该部分结果。

## 0.2.0 发行检查

复查客户端连接、消息身份、加密边界、持久化反射规则、权限与升级，以及 Worker 的认证、频道 / 邮箱路由、容量、休眠、队列过期和确认。沿用现有协议向量和回归，没有更换密码学算法或存储格式，也没有重新设计用户界面。

本次发现并修复的实际问题：

| 问题 | 触发方式 | 修复与回归 |
| --- | --- | --- |
| GATT 资源未关闭 | 停止后清空表，延迟任务读取空表或随协程取消 | 先取快照和清理状态，返回前逐一释放；撤销权限或重复停止也能完成其他连接清理 |
| 扫描器 / GATT 服务停止被跳过 | 停止函数排入任务后立即取消所属 scope | 同步停止；权限撤销也清除扫描状态，服务端关闭失败仍清除引用 |
| 尚在协商的连接泄漏或旧回调恢复连接 | MTU 前停止，随后迟到回调或迅速重启 | 跟踪待连接 GATT，按生命周期拒绝旧回调；服务端回调也绑定创建时生命周期 |
| 语言切换后部分文本仍用旧资源 | Compose 重组依赖普通 Context.getString | 使用 stringResource 获取进度和无障碍文案，保留布局与文本本身 |
| 发行身份依赖本机 debug 证书 | 换构建机器或丢失开发环境后发行 | 独立长期密钥、公共证书固定与签名迁移链；新增实际 APK 验证及附件打包工具 |

新增 12 项蓝牙回归使用合成地址、模拟 GATT 和虚拟调度器，覆盖同步释放、取消 scope、权限撤销、重复停止、待协商连接、迟到回调和重启。共享源码与测试同步进入 Wear。物理链路行为和升级数据保留仍需 [使用前验收](OPERATIONS.md)。

## 0.1.6 安装包精简

推荐 ARM64 精简预览代替通用 debug 日常安装，保留其他三种架构与通用包。手机最低 SDK 提高到 API 34，Wear 的最低 SDK 保持 API 33；旧定位权限从手机合并清单移除。R8 规则补齐反射读取的持久化模型，防止旧安装升级后 JSON 字段名称变化。

APK 检查直接读取产物中的 DEX，核对历史字段、JNI 与 WorkManager 入口，检查语言、字体、离线扫码和对齐，并对比各架构包的代码及资源。原包对比包括原生库和静态资产字节以及本地开发覆盖签名。没有改动用户界面、传输或加密算法。仍需在真机上用精简包验证冷启动、旧数据升级、权限、媒体及离线传输；不能把 debug 的单元测试成功当作 R8 后全功能已实测。

## 0.1.5 修复

| 问题 | 触发方式 | 最终行为 |
| --- | --- | --- |
| 失败连接在退避期间被旧回调恢复 | socket 失败后，旧连接迟到发送 challenge / ready | 失败时立即废弃连接 generation；旧回调不能认证或显示在线，只有新连接完成认证才能就绪 |
| 私聊对端收不到昵称更新 | 已知在线私聊对端没有共用频道，用户修改昵称 | 同一份签名公告通过该对端邮箱发送；不向无关频道广播，不从联系人历史枚举新目标 |
| 同名消息错误标为已读 | 对端使用与本机相同的昵称，在未打开的私聊中发送 | 未读及持久化优先按身份判断；自己的旧昵称消息仍属于自己，同名他人仍计为未读 |
| Android 模块说明与分支不符 | 直接阅读 android/README.md | 明确说明独立分支、实际功能、GPL-3.0 和正确构建 / 发行入口 |

上述连接与消息问题均保留最小合成回归。公告测试使用模拟 WebSocket、合成密钥和虚拟调度器，检查实际输出的数据包；未连接生产中继。身份判断由消息模型提供，UI、未读状态和会话显示名称共用同一规则；没有身份字段的历史消息才使用昵称回退。
