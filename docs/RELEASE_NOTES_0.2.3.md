# bitchat 0.2.3 — 流量私聊与送达回执修复

最低 Android 14（API 34），versionCode 11，沿用现有长期发行签名，可覆盖本分支 0.2.0 / 0.2.1 / 0.2.2。

## 修复

- 关闭蓝牙和 Wi-Fi 后，本地传输的旧对端记录与加密会话不再优先截获在线私聊。路由核对实际无线开关和蓝牙权限，再选择可用的服务器邮箱路径。
- 私聊保存失败或被 panic 拒绝时，不再发“已送达”回执。成功保存与已保存重复消息的身份 / 内容确认，才允许发送对端加密回执。
- 在线私聊文字未确认时，每 10 秒用当前 Noise 会话重新加密尝试；断网期间等待重连。最多暂存 100 条，5 分钟未获确认则标为失败。收到目标对端的送达或已读回执即停止该消息重试。
- 重复消息只补发已保存消息的回执，不重复加入聊天、计未读或触发通知。停止在线服务清空内存重试队列；本次未增加跨进程持久发件箱。

Worker 与通信线格式不变，无需重新部署 Cloudflare。密码派生、Noise 加密和原版界面继续保留。

## 验证与安装

新增合成回归覆盖关闭蓝牙后的旧会话路由、权限撤销、无本地无线的邮箱私聊接收、先保存后回执、界面挂载 / 脱离、重复确认、错误对端确认、重连、超时和停止。Noise 边界在邮箱接收测试中使用仅测试的替身；密码学由既有 Noise 向量单独覆盖，不将该合成测试冒充实体手机或公网验证。完整构建、测试与签名范围见 [验证记录](https://github.com/liaopinyi714/bitchat/blob/v0.2.3/docs/TESTING.md)。

推荐 ARM64 手机安装 `bitchat-android-arm64-v8a.apk`，不确定架构时用 `bitchat-android-universal.apk`。覆盖升级并保留原数据。

两台手机均需升级后，关闭 Wi-Fi / 蓝牙、保持移动数据联网，在同一频道确认对端在线，再双向发送新的测试文字；分别检查私聊打开、切换到其他页面和应用在后台的接收。确认消息显示后才推进送达状态；再用短时断网验证恢复且消息不重复。维护环境尚未执行这项双机真机检查，不能把本地自动回归写成已完成实际流量验收。
